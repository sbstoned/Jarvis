EXACT V36.2 TASKFORGE FAILURE REPLAY
-----------------------------------
The uploaded failed diagnostic project_20260828_211324 was re-read.
Its architecture failure text contained 5 concatenated structured JSON planning objects.
Those objects reconstruct to a 38-file TaskForge architecture.

V36.2 incorrectly rejected that architecture because it treated dependency metadata as literal source-file paths, including:
  frontend/node_modules
  backend/app:App
  backend/app.routes:routes
  backend/app.routes.projects:project_router
  backend/app.services.projects:project_service
  backend/app.repositories.projects:projects

Under V37 semantic dependency normalization:
  - node_modules is classified as external/package metadata and removed from source DAG edges.
  - sqlite3 and other runtime/package dependencies are external metadata, not source providers.
  - backend/app:App resolves to backend/app/__init__.py.
  - backend/app.routes:routes resolves to backend/app/routes/__init__.py.
  - backend/app.routes.projects:project_router resolves to backend/app/routes/projects.py.
  - backend/app.services.projects:project_service resolves to backend/app/services/projects.py.
  - backend/app.repositories.projects:projects resolves to backend/app/repositories/projects.py.

Replay result:
  reconstructed files:             38
  unresolved semantic dependencies: 0
  manifest completeness issues:     0

The prior user-facing "Bootstrap recovery exhausted without any materializable source" message was also traced to architecture/preflight failure falling through the legacy bootstrap error branch. V37 preserves architecture/preflight failures as their own actionable failure class instead.
